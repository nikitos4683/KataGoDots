# Движок KataGoDots: что изменено относительно `master`

Обзор движка на ветке `master-mine` в сравнении с `master` (`d01faacb`): что поменялось, как теперь устроены сеть, данные, обучение и инференс, и где читать подробности. Подробная спецификация сети — [DotsSparseNN.md](DotsSparseNN.md), правила игры в движке — [DotsRules.md](DotsRules.md), замеры и параметры цикла обучения — [DotsTrainingLoopTuning.md](DotsTrainingLoopTuning.md).

Движок теперь только для Точек. Go остаётся в коде как справочный (его плотные сети и тесты не тронуты), совместимость со старыми моделями и данными Точек не сохраняется.

---

## 1. Коротко: было → стало

| Часть | `master` | `master-mine` |
|---|---|---|
| Вход сети | Плотная сетка 39×32: 22 пространственные плоскости и 19 глобальных признаков (inputs v7) | Токены: одна точка = один токен, только выставленные точки вне окружений, плюс токен `GLOBAL` (inputs v8) |
| Окружения (области) | Плоскости на сетке | Не токены: их факты записаны в признаки граничных точек |
| Связность точек | Неявно, через свёртки по сетке | Движок даёт каждой точке номер цепи; внимание ствола получает обучаемое смещение по паре цепей |
| Ствол | Трансформер KataGo по всем 1248 клеткам, позиции из индекса клетки | Тот же трансформер (nested bottleneck, RoPE) по токенам точек, позиции из координат |
| Policy | Свёртка 1×1 по клеткам + пас | Декодер кандидатов: каждый разумный ход и заземление читают ствол через cross-attention |
| Ownership | По клеткам | По выставленным точкам (вероятность, что точку захватит соперник её владельца) |
| Головы seki и score-распределения Go | Были | Удалены |
| Версия модели | ≤ 17 | 18 (плотные модели Точек отклоняются) |
| Бэкенды | Все | Для Точек — CUDA (основной) и Eigen (CPU-эталон), остальные отклоняют модель |
| Обучающие данные | Плотные NPZ | Разреженные NPZ без дополнения, «только факты» |
| Самоубийство в конфигах | Разрешено | Запрещено (сеть учится только с этим правилом) |
| Решатель лестниц | Был (`dotsfieldLadders`) | Удалён вместе с признаками лестниц |

## 3. Вход сети: позиция как набор фактов

Извлечение — `NNInputs::fillDotsSparseInput` ([nninputsdotssparse.cpp](../cpp/neuralnet/nninputsdotssparse.cpp)), структура `DotsSparseInput` ([nninputs.h](../cpp/neuralnet/nninputs.h)). Движок пишет только целочисленные координаты и игровые счётчики; всю геометрию (масштабы, расстояния до краёв, RoPE) модель считает сама одной формулой в PyTorch и C++.

- **Точки** (`POINT`, 19 признаков после развёртки): владелец, расстояния до краёв, заземление, метка «поставлена k ходов назад» (до 5), и факты окружений, на границе которых точка: их число, точки игрока и соперника внутри, свежесть. Точки внутри окружений не токены. ([DotsSparseNN.md §3–4](DotsSparseNN.md#3-токен-point))
- **Цепи**: номер 8-связной компоненты точек одного владельца. Это не признак токена, а отношение пар: внимание ствола прибавляет к логиту пары обучаемое смещение по категории «одна цепь / один владелец / разные владельцы». Окружение — это замкнутая цепь, и голова может смотреть строго вдоль своей цепи. ([§3.1](DotsSparseNN.md#31-цепи))
- **Глобальные признаки** (8): заземление в истории, коми, разрешено ли заземление, счёт обеих сторон, перевес с коми, размеры поля. ([§5](DotsSparseNN.md#5-глобальные-признаки))
- **Кандидаты** — все разумные ходы (`getReasonableMoves`): 8 признаков, включая точный выигрыш очков от хода за себя и за соперника (`gain_my`, `gain_opp`, считаются ходом с откатом) и попадание в домики. Плюс один кандидат-заземление с его итоговым счётом. ([§6.2](DotsSparseNN.md#62-кандидаты-действий))

На поле 39×32 в среднем ~500 точек и ~690 кандидатов, их сумма почти всегда около площади поля (1248): пустое поле не исчезает, оно уходит в декодер, который в несколько раз дешевле ствола.

## 4. Модель (версия 18)

Код: [model_sparse_dots.py](../python/katago/train/model_sparse_dots.py). Целевая модель — `b5c384h6nbttflrs-fson-silu-rsnh`; для Точек любое имя трансформера даёт разреженную модель.

- **Эмбеддинг**: `Linear(19→C)` для точек, обучаемый токен `GLOBAL`, глобальные признаки прибавляются ко всем токенам.
- **Ствол**: штатные блоки KataGo `NestedBottleneckTransformerBlock` (1×1 → [RMSNorm → внимание → SwiGLU] ×2 → 1×1), работают с любой длиной последовательности.
  - RoPE с обучаемыми частотами по целым координатам точек. Начальные частоты от 1/50 до π радиан на пункт (у плотной модели до 1): сетки нет, и различать соседние пункты сеть может только через RoPE.
  - Смещение цепей в каждом слое внимания (таблица 3 значения на голову, стартует с нуля).
- **Декодер кандидатов**: запрос кандидата = его признаки + пулинг ствола, затем 1 слой `cross-attention к токенам ствола → SwiGLU FFN`. Кандидаты между собой не общаются. Выход — 6 policy-логитов (используются 0 и 5) и 2 futurepos на кандидата; общий softmax по всем кандидатам и заземлению. ([§6.3](DotsSparseNN.md#63-декодер-кандидатов))
- **Value-голова** — как у KataGo, на пулинге ствола; ownership — логит на каждую точку. Головы seki и score-распределения Go удалены, центры бинов score-belief для Точек исправлены. ([§6.5–6.7](DotsSparseNN.md#65-ownership))
- **Файл модели**: формат версии 17 с разделом `sparse_dots_model` (эмбеддинги, ствол, таблицы смещений цепей, декодер, value-голова). ([§9](DotsSparseNN.md#9-файл-модели-версии-18))

Почему декодер, а не policy-голова KataGo: у KataGo каждая пустая клетка — свой токен ствола, и голова читает готовый вектор. Здесь пустых пунктов в стволе нет, поэтому кандидат один раз спрашивает ствол, какие его выводы относятся к этому пункту; RoPE в весах внимания адресует эти выводы по сдвигу.

## 5. Инференс в C++

- **Поиск не менялся**: `NNEvaluator` ([nneval.cpp](../cpp/neuralnet/nneval.cpp)) строит `DotsSparseInput` вместо плоскостей, выход раскладывается в обычный `NNOutput` (логиты кандидатов — по их пунктам, заземление — в пас, ownership точек — в карту владения). Хеш кэша включает последние 5 ходов.
- **CUDA** — [cudasparsedotsmodel.cpp](../cpp/neuralnet/cudasparsedotsmodel.cpp), ядра — [cudasparsedots.cu](../cpp/neuralnet/cudasparsedots.cu), внимание — [cudaflashmma.cuh](../cpp/neuralnet/cudaflashmma.cuh):
  - батчи **без дополнения** (varlen): токены и кандидаты всех позиций идут подряд, границы — смещения. С дополнением строк было почти вдвое больше, чем у плотной модели: в батче из разных партий точки и кандидаты антикоррелированы;
  - одна GEMM на Q/K/V, на K/V декодера, на `linear1`+`gate`; RoPE считается в ядре поворота; общие рабочие буферы; вход в постоянном pinned-буфере;
  - внимание — tensor-core ядро в режиме varlen, смещение цепей добавляется в нём же (коды ключей грузятся вместе с тайлом K/V);
  - ствол и декодер в FP16, эмбеддинги и value-голова в FP32.
- **Eigen / CPU-эталон** — [sparsedotsnn.cpp](../cpp/neuralnet/sparsedotsnn.cpp): одна позиция без дополнения в FP32, те же формулы; с ним сверяются CUDA и PyTorch.
- Скорость на RTX 5060 Ti — [DotsTrainingLoopTuning.md](DotsTrainingLoopTuning.md).

## 6. Данные и обучение

- **Формат NPZ** ([sparse_dots_npz.py](../python/katago/train/sparse_dots_npz.py), [§7](DotsSparseNN.md#7-формат-обучающих-данных)): массивы точек и кандидатов всех строк подряд, без дополнения; цели policy и futurepos — только для кандидатов, где они ненулевые; распределение счёта — два соседних бина; малые значения в int8; номер цепи точки — `pointChainP`. Файлы старых форматов отклоняются.
- **Цель variance time** для Точек ограничена: в длинных партиях с шумной оценкой (необученная сеть, мало визитов) сумма `Σ t·ΔWL²` росла с квадратом длины партии и разгоняла обучение до остановки. ([§6.7](DotsSparseNN.md#67-головы-позиции))
- **Загрузчик** ([data_processing_sparse_dots.py](../python/katago/train/data_processing_sparse_dots.py)): батч дополняется только до своего максимума, строки группируются по длине (куски по 32 батча сортируются по числу точек), батчи собираются в процессах-воркерах (`KATAGO_SPARSE_DOTS_DATA_WORKERS`, по умолчанию 2), симметрии — только преобразование координат.
- **train.py**:
  - `torch.compile` с динамическими формами; на Windows сам находит MSVC;
  - внимание ствола — flex attention, смещение цепей считается в ядре; градиент таблицы копится в её копиях по позициям (иначе атомарные сложения в несколько адресов замедляли внимание в ~8 раз); валидация — через SDPA;
  - декодер в FP16 под autocast, логиты и value-голова в FP32;
  - потолок памяти CUDA на Windows (`KATAGO_CUDA_MEMORY_FRACTION`, 0.9), чтобы драйвер не выносил излишек в системную память;
  - исправлены неверные градиенты flex attention под `torch.compile` (оптимизация раскладки Inductor отключается).

## 7. Правила и selfplay

- Самоубийство запрещено по умолчанию (`Rules::DEFAULT_DOTS`, во всех конфигах Точек); правила с разрешённым самоубийством sparse-модель не поддерживает. ([§6.1](DotsSparseNN.md#61-самоубийство-и-домики))
- Заземление считается разумным только для игрока, который им не проигрывает (раньше и проигрывающий мог заземлиться).
- Старт selfplay и матчей из позиций SGF (`startPosesFromSgfDir`, в том числе `.sgfs`): партия играется по правилам своего SGF, загрузка быстрая (позиции партии делят один образец), `startPoses` нужен только для партий с нуля.

## 8. Инструменты

| Команда | Что делает |
|---|---|
| `katago testsparsenn -model M [-use-fp16 true]` | Сверка бэкенда сборки (CUDA) с CPU-эталоном на позициях случайных партий |
