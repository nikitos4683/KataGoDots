# План реализации разреженной нейросети для Точек

Спецификация: [DotsSparseNN.md](DotsSparseNN.md). Правила: [DotsRules.md](DotsRules.md).

Принципы:
- **Каждый этап заканчивается тестами**, которые проходят до перехода к следующему.
- **Есть эталон для сравнения.** PyTorch — эталон модели, CPU-бэкенд Eigen — эталон C++. CUDA сверяется с обоими.
- **Этапы 0–4 делаются и проверяются в облачной песочнице (Linux, без GPU).** Этап 5 (CUDA) требует RTX 5060 Ti: код пишет Claude, запуск — на машине разработчика, разбор вывода — снова Claude.
- **Go не затрагивается.** Его входы, модели и бэкенды остаются как есть.

## Этап 0. Основа

- Рабочая ветка `dots-sparse-nn` от `master-mine`.
- `Rules::DEFAULT_DOTS`: самоубийство запрещено по умолчанию (§6.1). Поправить тесты, которые на это опираются.
- Версии:
  - новая версия модели **18** — «Точки, разреженный формат»;
  - C++ отказывается загружать Dots-модели старых плотных версий с понятным сообщением об ошибке.

**Проверка:** `katago runtests` и `pytest` зелёные.

## Этап 1. C++: извлечение позиции из движка

Структура `DotsSparseInput` и функция её заполнения (`nninputsdots.cpp`). Внутри только целочисленные факты (§7.1):

- **Точки:** `owner`, `grounded`, `movesAgo`, координаты.
- **Области:**
  - внешние контуры по финальному состоянию доски: 4-связные компоненты выключенных пунктов одного активного цвета;
  - граница — точки владельца, примыкающие к компоненте;
  - сверка с `Base::surrounding_locs` там, где база ещё в истории;
  - счётчики, `grounded` («хотя бы одна»), `movesAgo`.
- **Кандидаты:**
  - из `getReasonableMoves`;
  - `gain_my` / `gain_opp` из `CapturesAndTerritoriesInfos` (сохранять `captures_diff` баз, которые сейчас выбрасываются);
  - домики.
- **Заземление:** разрешено ли, `ground_result`.
- **Глобальные признаки** (§5).

Отладочная команда `katago dumpsparse`: позиция из SGF → JSON для глазной проверки.

**Тесты:**
- Позиции, построенные вручную: простое окружение, вложенный перезахват, несколько областей одним ходом (5.9), домик и ход в чужой домик (5.14, 5.16), заземление.
- Стресс-тест на случайных партиях. Инварианты:
  - сумма `insideOpp` по моим областям = мои захваты по движку;
  - перезахват ровно одной области даёт в движке `captures_diff = −(n_X + n_O + |B|)`;
  - бит `grounded` одинаков на всей границе области;
  - извлечение из отражённой/повёрнутой доски = преобразованное извлечение;
  - кандидаты = `getReasonableMoves`.

## Этап 2. PyTorch: модель

- Загрузчик батчей с дополнением до максимума батча и масками; симметрии через преобразование координат.
- Геометрия из целых координат: `x/40`, края, Фурье-признаки вершин.
- Модули:
  - эмбеддинг `POINT`;
  - кодировщик области (MLP по вершинам → mean ‖ max ‖ log len → MLP);
  - ствол `b5c384h6nbttflrs-fson-silu-rsnh` на токенах с маской;
  - усреднённый RoPE (`area_rope = mean | none`);
  - декодер кандидатов (`candidate_decoder_layers`);
  - головы: 6 policy + 2 futurepos на кандидата, ownership на `POINT`, скалярные головы.
- Функции потерь: policy по общему softmax M+1, ownership, futurepos; скалярные — из `metrics_pytorch.py` с поправкой на площадь поля.
- Экспорт в `.bin.gz`: новые секции (эмбеддинги, кодировщик области, декодер).

**Тесты:**
- **Инвариантность к паддингу:** дополнительные нули не меняют выходы.
- **Эквивариантность:** симметрия входа даёт ту же перестановку policy и ownership.
- **Тождество усреднённого RoPE:** логит к области = среднее логитов к её вершинам.
- **Переобучение:** модель заучивает крошечный синтетический набор.
- **Экспорт:** круговое преобразование checkpoint → `.bin.gz` → чтение Python-ридером.

## Этап 3. C++: CPU-эталон (Eigen)

- Чтение новых секций модели (`desc.cpp`).
- Прямой проход разреженной модели в `eigenbackend.cpp`. Трансформерные блоки в Eigen уже есть.
- `NNEvaluator`:
  - выходы переменной длины (кандидаты, ownership по точкам) раскладываются обратно на пункты поля;
  - симметрии;
  - ключ кэша учитывает всё содержимое входа.

**Тесты:**
- Выходы Eigen совпадают с PyTorch на наборе позиций, допуск ~1e-4 в FP32.
- `katago gtp` с моделью со случайными весами ходит без падений.

## Этап 4. Данные selfplay и цикл обучения

- `trainingwrite.cpp`: новые массивы NPZ (§7.2), цели:
  - проекция policy соперника;
  - futurepos по цвету постановки;
  - ownership по `finalOwnership`.
- `shuffle.py` с повторным дополнением, загрузчик реальных файлов.

**Тест сквозного цикла в песочнице (Eigen):** selfplay случайной сетью → NPZ → shuffle → 100 шагов обучения → экспорт → загрузка в C++ → новый selfplay.

## Этап 5. CUDA (на RTX 5060 Ti)

Новые ядра и изменения в `cudaandrocmbackend.inc`:
- последовательность токенов как «доска» 1×S с маской;
- `seqLen` округляется до кратного 64 (кэш графов cuDNN);
- RoPE по буферу координат и усреднённый RoPE по множествам вершин (одно ядро);
- segment-reduce (mean/max) для кодировщика области;
- cross-attention декодера через SDPA с разной длиной Q и KV;
- gather/scatter выходов.

**Тесты** (запускаются на твоей машине):
- CUDA против Eigen на тех же позициях, допуски для FP32 и FP16;
- `katago benchmark`: скорость, подбор `numSearchThreads`.

## Что не поддерживается

Разреженные Dots-модели работают только на **CUDA** и **Eigen**. OpenCL, TensorRT, ONNX, Metal и ROCm на них выдают понятную ошибку. ROCm использует общий с CUDA код и может заработать почти бесплатно, но не тестируется. Для Go всё по-прежнему.
